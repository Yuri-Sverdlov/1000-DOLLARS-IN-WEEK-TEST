## 5. Методика независимой проверки

Одного числа недостаточно: если реализация повторяет логику проверяемого кода, проверка
ничего не доказывает. Поэтому «лишние копии» посчитаны **тремя разными способами** и сверены.

| № | Способ | Как считается | Значение |
| --- | --- | --- | --- |
| 1 | `pandas.duplicated()` | как в уроках 1–3: сравнение по всем 8 колонкам, `sum()` | **79** |
| 2 | Чистый Python | каждое значение нормализуется, строка → кортеж, кортежи считает `collections.Counter`; лишние копии = Σ(частота − 1) по группам | **79** |
| 3 | Контроль по остатку | `len(sales) − len(sales.drop_duplicates())` = 5 000 − 4 921 | **79** |

Способ 2 — именно независимая реализация: он не вызывает код pandas для сравнения строк,
а работает с обычными кортежами Python.

### 5.1. Тонкость: пустые ячейки (важно!)

`pandas.duplicated()` считает два `NaN` **равными** друг другу. В обычном Python
`float('nan') != float('nan')`, поэтому наивная реализация на кортежах дала бы **заниженное**
число: строки с пустым `Customer ID` не склеились бы.

В скрипте это учтено: пустое значение заменяется текстовым маркером `"<пусто>"` (`normalize()`),
и только после этого строка превращается в кортеж. Именно поэтому способы 1 и 2 дают одно и то же
число 79. **Если будете переписывать скрипт — эту нормализацию нельзя убирать.**

### 5.2. Структурная сверка числа

Дополнительная арифметическая проверка целостности:

```
строк в группах совпадений 153  =  74 группы × 1 «оригинал» + 79 «лишних копий»
```

Сходится, значит группы посчитаны корректно (а не «79 из ниоткуда»).
